# Security Policy

## Scope

This repository is primarily documentation, prompts and templates. It does not provide a production runtime or accept application credentials. Security-sensitive defects may nevertheless exist in examples, scripts, workflow configuration or guidance.

## Reporting a vulnerability

**Do not report a suspected vulnerability in a public Issue or Discussion.** Use GitHub's private vulnerability reporting feature for this repository when it is enabled. Otherwise, contact the repository owner privately through their GitHub profile.

Include a concise description, affected file or workflow, potential impact, and safe reproduction steps. Do not include real credentials, personal data, client information or production secrets.

## Response expectations

This is a community project and does not currently promise a response-time SLA. Maintainers will assess reports as capacity allows, keep details private while investigation is active, and coordinate a correction or mitigation before public disclosure where appropriate.

## Contributor safeguards

- Never commit secrets, credentials, tokens, private keys or connection strings.
- Do not place sensitive values in examples, screenshots, logs or test fixtures.
- Use synthetic identities, URLs, payloads and architecture examples.
- Review GitHub Actions permissions and third-party actions before changing workflows.
