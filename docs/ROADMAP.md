# Roadmap

This roadmap is a starting point for community discussion, not a promise of delivery dates. Priorities should change as maintainers learn from feedback.

## v1.0 — Initial playbook

- [x] Recommended strategy, lifecycle and decision gates.
- [x] Implementation order and target architecture guidance.
- [x] API contract, functional parity and testing guidance.
- [x] Technical decision guidance for MediatR, FluentValidation, FluentAssertions, Polly integrations and .NET 10/C# 14.
- [x] Reusable AI prompts and templates.
- [x] Contribution, security and feedback process.

## Near-term candidate improvements

- [ ] Collect sanitized feedback from teams applying the prompts to different API styles.
- [ ] Add more synthetic examples for controllers, Minimal APIs and hybrid solutions.
- [ ] Add concrete parity harness examples for HTTP contracts and side-effect comparison.
- [ ] Add sample test strategies for database, messaging and external HTTP dependencies.
- [ ] Validate prompt outputs across more than one AI coding agent.
- [ ] Improve the technical decision matrix based on observed migration outcomes.

## Longer-term ideas — subject to community interest

- [ ] A small sample API repository demonstrating a vertical slice and parity harness.
- [ ] Optional machine-readable assessment and modernization-plan schemas.
- [ ] Optional scripts for checking documentation links and prompt consistency.
- [ ] A versioned maturity model for test and parity readiness.
- [ ] An anonymized collection of modernization patterns and anti-patterns.

## How to influence the roadmap

Open an improvement proposal with the problem, expected benefit, evidence and any trade-offs. The community should prefer reusable, low-assumption guidance over project-specific prescriptions.
